# SP106 — One-click private job application package

**Baseline:** \`431de3cccdf539ce5470518c513ecaddb0295732\`, tested SP105 PR #272. Proposed stack: #270 → #271 → #272 → SP106. This PR does **not** merge or deploy anything by itself.

## User goal and acceptance

In the existing **My applications** studio, a signed-in applicant can download one ZIP that contains the *exact saved revision* of their selected private job application:

- Full job-specific CV in editable DOCX and printable PDF.
- Full job-specific cover letter in editable DOCX and printable PDF.
- \`README-NOT-SUBMITTED.txt\` explicitly stating this is only document preparation, **not** a submitted employer application.

The download is available in Manual and Assisted flows and as a way to save a copy of an existing application record. When either editor has **unsaved edits**, the package link is disabled, with an explanation that only the already-saved documents can be exported. After saving, the same job's link re-enables. Revisions, the master CV and the original cover letter remain unchanged by a GET download; it is not a review approval, agent job, submission attempt, acknowledgment, or contact with any employer.

## Reuse, security, performance, accessibility

- New server code composes four files from first-party \`smartploy/application_workspace.py::render_document\`, used by the already-live per-file download routes. It does not implement or duplicate its own document conversion, CV parsing, AI completion or identity check.
- The API reuses \`tenant_context(request)\` and \`workspace_repository.get(profile_id, workspace_id)\` on each GET; nonexistent/not-owned IDs yield 404.
- All ZIP member names are derived from existing bounded, lower-case ASCII \`_slug\` values, without user-controlled path separators, directories or absolute paths. Static README cannot embed candidate CV content.
- Maximum cumulative uncompressed generated bytes and resulting ZIP bytes are **8 MiB**; each constituent render already enforces \`MAX_DOCUMENT_BYTES=4 MiB\`. Everything is built in memory without writing employer or application data to server filesystem.
- Stable ZIP member timestamps and ordinary standard-library ZIP compression; no additional dependencies. Headers: \`Cache-Control: private, no-store\`, \`Pragma: no-cache\`, \`X-Content-Type-Options: nosniff\`, \`Content-Security-Policy: sandbox\`, ZIP Content-Type and attachment filename.
- The frontend uses a semantic \`section\`, full link label, responsive layout, keyboard focus where enabled, and clear dirty-disabled copy. No personal text is added to URLs or app/browser storage.
- Backend tests verify real DOCX and PDF structure, applicant-approved content only, private headers, safe ZIP paths, 404, and zero change to \`actually_submitted\`; browser synthetic test verifies exact download filename after a saved revision.
