# BEST-FIT-TECH-001 — Mandatory Best-Fit Engineering and Capability Resolution

**Owner directive, 2026-11-19.** Applies to all owner-authorized existing and future projects, UI, backend, security, data, voice, AI, documentation, infrastructure, testing and deployment. Complements REA-FIRST-001, FEATURE-FIRST-001 and OBUM-UI-PORTFOLIO-3.0. **Precedence:** law, latest approved project requirements, safety/privacy/security, current incident holds, protected branches, identity and release approval always control. This standard does not license unauthorized copying, autonomous payments, credentials or releases. Independent peer **code** review is optional under owner policy dated 2026-11-18; maintainer exact-SHA technical review remains mandatory.

## Mandatory first-turn acknowledgement and discovery

Before starting **or continuing** implementation, read root AGENTS.md and the relevant native instruction surface (CLAUDE.md, GEMINI.md, GitHub Copilot, Cursor) plus latest approved plan and security rules. The **first substantive reply** in a repository-aware agent session must begin `BEST-FIT-TECH-001 acknowledged` and name repo, authoritative specification/requirement, exact baseline if accessible, single smallest user action -> visible result, existing/reusable implementation, relevant skills, missing tools, planned tests and current release holds. Never claim a missing file or skill was read, that a mock is production, or that a tool was executed when it was only described.

## The enforceable component loop

1. **Inspect** current source, branch, history, open PRs, previous donor receipts, production behavior, toolchain, security restrictions and the latest approved specification. Keep the actual user outcome primary; don't generate an architecture plan instead of the smallest qualified working feature.
2. **Compare before writing** current implementations, authorized sibling repos, and mature appropriately licensed upstream source. Investigate credible SDKs, test tools, design systems, research and media as leads, not automatic copying rights. Consider authorized REA (morluto/rea), record APPLIED/NOT_APPLICABLE/BLOCKED with outputs. Document meaningful alternatives proportional to risk, not a perpetual research loop.
3. **Choose best fit** for function, legal license, security, privacy, visual quality, accessibility, measured resource/performance, reliability, compatibility, maintainability, user experience, time to working release and cost. Use C/C++/Rust/WASM when warranted; do not rewrite a CSS issue in C or add microservices just for language diversity. A proven working component is preferable to speculative novelty.
4. **Actually run skills** applicable to the affected component: vetted version/pin, what was executed, inputs/outputs and actual before/after. For UI apply suitable approved frontend-design/apple-design/ui-ux-pro-max/Impeccable/mobile-native/break-ui or qualified equivalents to real rendered screens; for non-UI use relevant engineering test/build workflow. If unavailable, record SKILL_GAP and use a verified equivalent. Reading or naming SKILL.md is not execution.
5. **Resolve missing tools proactively**: discover installed compilers/SDKs/caches and current project dependencies, existing authorized CI runners and containers. Obtain official, pinned, license/security-checked tools in isolated least-privilege environments where permitted; verify checksums/signatures as available; compile/run and record results. If new permission, payment, credential, system change or external target authorization is needed, request the smallest exact action and keep unaffected work moving. Never run unreviewed installers as root, change production hosts without authority or silently downgrade technology due to a missing compiler.
6. **Adopt permitted code**: for each donor give original repository URL, full SHA/tag, source file/function, license, unchanged/copied section, sanitized/ported/adapted section, destination, integration point and tests. Mark COPIED, PORTED, SANITIZED, ADAPTED, INTEGRATED, NEW and NOT_VERIFIED distinctly. If none, state `Copied: none` and justify. REA reconstruction != source provenance.
7. **Design down to pixels and words**: use governed semantic tokens with product-specific identities for font family, scale, weight, line height, color role, measured contrast, spacing, geometry, icons, borders, component states, localization, keyboard/focus, motion and copy. Show real desktop/tablet/mobile and FI/EN where applicable. Test light/dark, long/empty/loading/error/denied/retry, high contrast/reduced motion. WCAG 2.2 AA baseline unless stricter. Use real audio state for microphone rings and real progress for animations; remove decorative distractions. Real screenshots, visual regression and human/agent optical inspection are required for changed UI, not just bounding-box tests.
8. **Verify and secure**: native unit/integration/contract, negative, auth/role/tenant, privacy, supply chain/license, accessibility, performance (when materially relevant), recovery and rollback tests; real-browser/browser-engine coverage where affected. Report skipped/NOT_RUN honestly. Do not weaken tests to get green. Check actual artifacts, not `PASS` text alone.
9. **Release actual user outcomes**: use original designated Woodpecker/ObumDelivery and exact-SHA immutable artifact controls, approved authority, release and recovery. Maintain SOURCE_READY, CI_QUALIFIED, STAGED, DEPLOYED and USER_VERIFIED separately. The real authorized user must complete the intended task from product/launcher and see correct result. Never bypass incident HOLD, legally mandated approval or protected rules.
10. **Report compactly**: source diff, precise donor/skill/toolchain executions, commands and results, real screenshot/golden journey, CI SHA/digest, deployed URL/user-access state, blockers and next smallest qualified feature. Avoid planning-only loops.

## Required repository entrypoints

Root `AGENTS.md` for generic agents/Codex; root `CLAUDE.md` for Claude Code; root `GEMINI.md` for Gemini CLI; `.github/copilot-instructions.md` for Copilot; `.cursor/rules/best-fit-tech.mdc` with alwaysApply for Cursor. Each must contain this policy ID and defer to current approved requirements. Preserve existing instructions: append/prepend, never erase. An AI platform may not automatically read another vendor's file; only connected repository-aware agents are in reach.

## Portable evidence gate

The self-contained `quality/best_fit_gate.py` validates the entrypoints and optionally per-feature evidence JSON. Run `python3 quality/best_fit_gate.py --root . --bootstrap-only` for repository adoption and `python3 quality/best_fit_gate.py --root . --evidence relative/path.json` for an affected feature. Provide real relative proof paths for skill/toolchain execution and functional/security/recovery/visual/accessibility/performance checks, real provenance and technology decision. UI visual/a11y exemptions fail. `BLOCKED` tooling cannot be marked qualified. The validator checks **presence/structure of evidence, not truth or visual beauty**; browser verification and approval still matter. Native CI must execute the gate and GitHub branch rules must require that status if it is to prevent merging. A YAML file and repository policy alone are not protected rules.

## Future repositories; rollout

The original ObumDelivery new-repo bootstrap must install these entrypoints, validator, evidence template and CI job **before first feature work**, preserve local rules, and test failing/valid scenarios. Roll existing active repositories via feature-scoped PRs, no rewriting of working code or mass interruption of approved releases. Do not call a PR, unregistered Woodpecker job, or unprotected status `fleet-enforced`. All enforcement needs measured receipts.

## Important scope limit

No repository file, optional ChatGPT skill, or GitHub check can compel arbitrary unconnected AI conversations to read it. ChatGPT-level skills/custom instructions require installation in that product and other agent tools require explicit native configuration. A truthful implementation covers connected repo agents and actual qualified CI, not an impossible assertion that every AI everywhere is technically incapable of ignoring instructions.
