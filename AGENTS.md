# SmartPloy — Agent Delivery and Reuse-First Rules

These rules apply to all future coding and reviewing agents once this document has been approved and merged. Until then, treat this documentation PR as a proposal, not authority to deploy or submit applications.

1. **Read before work:** [Master project plan](docs/PROJECT_PLAN.md) §§1–18, [external/internal audit](docs/REUSE_FIRST_AUDIT_2026-10-18.md), relevant issue and current integrated PR/CI/deployment receipts. Reconfirm live refs.
2. **Search before writing or rewriting:** SmartPloy main and current integrated review, all relevant open PRs, ObumAI application/browser modules and specialist draft branches, then other owned repos, then external GitHub source linked from YouTube/TikTok. Do not create duplicate browser engines, profile databases, queues, job adapters, CV/letter generators or ATS tests without proving a gap.
3. **File a REUSE-CHECK:** Use [this template](docs/REUSE_CHECK_TEMPLATE.md), link it in every implementation PR and pin each candidate source commit/file/blob/LICENSE/NOTICE, dependency terms, quality, egress, exact employer rights, security findings and measurable gap. Distinguish actual running code from README, demo, fixture, draft or marketing claims.
4. **Legal boundary:** MIT/Apache code may be eligible after license/NOTICE/file/dependency checks. Unlicensed code cannot be copied; AGPL/GPL/Commons-Clause/source-available code may require source obligations, architecture changes or commercial permission. Merely modifying/rewording protected code does not cure rights. Do not use unauthorized LinkedIn/Indeed automation, CAPTCHA bypass or covert anti-bot evasion.
5. **Safety/tenant constraints:** Never reveal passwords, OAuth secrets, signed cookies or applicant documents in logs/issues. Keep SmartPloy tenant-scoped profile/attempt/consent/receipt truth and isolated browser session. Default external LLM/model egress OFF. ObumAI is a bounded versioned service, not a shared database or bypass for user/publisher consent.
6. **Application authority:** Synthetic UI fill, staged file or browser click does not prove an application. One-shot verified job+profile+document, approved employer channel, exact file readback, explicit final authority, duplicate-denial, UNKNOWN on ambiguous outcomes, truthful employer confirmation and applicant-controlled cancellation are mandatory.
7. **CI and release:** Preserve existing SmartPloy/ObumDelivery architecture; isolated exact-head tests with adverse cases and true staging/production/browser receipts. Do not claim ObumDelivery from a YAML file, GitHub Actions alone, or a Cloudflare build. Do not merge, deploy, activate unattended applications, transmit applicant PII or submit to employers without distinct reviewed owner authorization.
8. **Delivery reports throughout the work:** At meaningful checkpoints report DONE, IN PROGRESS, NOT STARTED and BLOCKED separately with GitHub links, SHA, CI and deployment evidence, and a grounded remaining-time estimate or explicitly unknown. Do not suppress skips, failing tests or missing rights.
9. **Current overlap:** SmartPloy [integrated draft #149](https://github.com/galapoto/smartploy/pull/149), [plan draft #150](https://github.com/galapoto/smartploy/pull/150) and [SP13 attachment draft #151](https://github.com/galapoto/smartploy/pull/151) may move independently. Review current heads before new changes; never overwrite another agent's source or redo its implemented portion.

**Until the owner reviews this expanded plan, the present work remains research/documentation only: no third-party source copied, employer contacted or production release claimed.**
